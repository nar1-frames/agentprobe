# Offline demo

Run a real AgentProbe scan with no API keys, no Ollama, and no network:

```bash
python -m pip install agentprobe-security   # or, from a clone: pip install -e ".[dev]"
agentprobe demo
# equivalent to (from a clone):
agentprobe scan --non-interactive --verbose --config agentprobe/demo/replay.yaml
```

The demo config and its recording ship inside the package
(`agentprobe/demo/replay.yaml` and `agentprobe/demo/scan.replay.json`), so
`agentprobe demo` runs from any folder. A relative `replay_path` is resolved
next to the config file that names it; reports go to `./reports` under the
current directory. If the packaged files are missing, `agentprobe demo` says
so and exits 2. It finishes in about a second, prints each attack's verdict
tag and a per category tally, then the scan summary, and writes an HTML
dashboard and a JSON report to `reports/`, through the same scanner code path
as a live scan. The only difference is the `replay` provider in the demo
config, which serves the recorded responses instead of calling a model.

If you just want to read the output, the committed sample is in
[`docs/demo/`](../docs/demo/): `demo_report.html` and `demo_report.json`.

## What the demo covers

14 attacks from three categories (`role_confusion`, plus `context_manipulation`
and `tool_misuse` at HIGH severity or above). The result is a mix of verdicts:
10 SAFE, 3 VULNERABLE, and 1 PARTIAL. The PARTIAL (`tool_misuse:2`) is a
hedge-then-comply case: the model says it cannot run code, then describes the
output anyway.

## Where the recording comes from

The recording was re-cut from an earlier local scan of `openai/gpt-oss-20b`
(target) judged by `openai/gpt-oss-120b`. No new model calls were made to build
it. `demo/build_replay.py` did the conversion:

- Target responses are the source scan's responses, trimmed to 900 characters
  where longer (marked `[response trimmed for the demo]`).
- Judge replies are rebuilt from the source scan's recorded verdict and reason,
  in the judge's two-line `VERDICT:` / `REASON:` format. The source report
  stores the parsed verdict and reason, not the judge's raw text, so these are
  reconstructions of that ruling, not byte-for-byte judge output.
- The requests themselves are generated by the real scanner, so their digests
  match what `agentprobe/demo/replay.yaml` sends.

The judge (120B) is larger than the target (20B), so the judge-must-be-stronger
gate passes on parameter size. No `strength_rank` override is set.

The recording was reviewed for keys, absolute paths, email addresses, and
hostnames before it was committed. It is the one `*.replay.json` file allowed
in the public tree (see `.gitignore` and `research/public_hygiene.py`).

Demo verdicts describe one recorded run of one model. They are an example of
the report format, not a benchmark result.
